# REST API системы управления фитнес-центром (Часть 1)

Серверное приложение на Python для управления клиентами и тренерами фитнес-центра. В этой части работы данные хранятся в оперативной памяти (в обычных словарях Python), без подключения базы данных.

## Выбор технологий

Для выполнения задания я выбрал следующий стек:
* **Python 3.13** и фреймворк **FastAPI** — он простой в настройке, быстро работает и сам генерирует страницу Swagger UI (`/docs`), через которую удобно тестировать запросы без Postman.
* **Pydantic** — используется для проверки входных данных (формата даты, email, номера телефона). Если данные неверные, сервер перехватывает ошибку и возвращает код `400`.
* **Uvicorn** — локальный сервер для запуска приложения.
* **Хранилище** — словари в оперативной памяти (`dict`), где ключом выступает `UUID` записи.

## Реализация и структура кода

Весь код находится в файле `main.py`, но логически разделён на независимые классы, чтобы во второй части работы можно было легко заменить работу со словарями на реальную БД, не переписывая сами эндпоинты:

1. **Модели (`Trainer`, `Client`, `ClientDetail`, `TrainerDetail` и др.)** — описывают поля сущностей, допустимые статусы тренера (`WORKING`, `ON_LEAVE`, `NOT_WORKING`) и правила валидации.
2. **Репозитории (`InMemoryTrainerRepository`, `InMemoryClientRepository`)** — отвечают только за сохранение и поиск данных в памяти. В следующем отчёте здесь будут запросы к базе данных.
3. **Сервис (`FitnessService`)** — основная логика: проверка, существует ли клиент или тренер (если нет — возвращается `404`), привязка тренера к клиенту и сборка подробных карточек с вложенными объектами.
4. **Роутер (`APIRouter`)** — принимает HTTP-запросы по пути `/api/...` и возвращает JSON с нужным кодом ответа (`201` при создании, `200` при чтении и обновлении).

## Как запустить

1. Установить библиотеки:
   ```bash
   pip install fastapi uvicorn pydantic[email]
   ```

2. Запустить сервер:
   ```bash
   python main.py
   ```

3. Открыть в браузере документацию для проверки запросов:
   ```text
   http://localhost:8000/docs
   ```

## Список эндпоинтов

Все запросы принимают и возвращают JSON.

### Клиенты
* `POST /api/clients` — создание нового клиента (`201 Created` или `400 Bad Request`)
* `PUT /api/clients/{id}` — полное обновление данных клиента (`200 OK`, `400`, `404`)
* `GET /api/clients` — список всех клиентов (`200 OK`)
* `GET /api/clients/{id}` — информация о конкретном клиенте (`200 OK`, `404 Not Found`)
* `GET /api/clients/{id}/detail` — подробная карточка клиента с вложенным объектом тренера (`200 OK`, `404`)
* `PATCH /api/clients/{id}/status` — смена активности клиента `is_active` (`200 OK`, `404`)
* `POST /api/clients/{clientId}/trainer/{trainerId}` — назначение тренера клиенту (`200 OK`, `404`)

### Тренеры
* `POST /api/trainers` — создание нового тренера (`201 Created`, `400`)
* `PUT /api/trainers/{id}` — обновление данных тренера (`200 OK`, `400`, `404`)
* `PATCH /api/trainers/{id}/status` — изменение статуса тренера (`200 OK`, `400`, `404`)
* `GET /api/trainers/{id}/detail` — подробная карточка тренера со списком его клиентов (`200 OK`, `404`)
* `GET /api/trainers` — список всех тренеров (`200 OK`)
